## What is this?

**HAWK 370** is a Slotket adapter that runs Socket 370 CPUs (Intel Mendocino / Coppermine / Tualatin, VIA Samuel / Ezra / Nehemiah) on 440BX motherboards. Its latest revision carries an **ESP32‑C3 SuperMini**, and this repository is the firmware for it.

The ESP32 drives the CPU's `STPCLK#` pin with a hardware‑timed pulse pattern generated by its RMT peripheral. The CPU spends part of every period in Stop Grant, so it runs slower. Old games and benchmarks that are too fast on a Pentium III become playable again. Everything is controlled from a web dashboard served by the module itself: no companion app, no cloud, just your local network.

> ⚠️ **Pre‑bring‑up firmware.** The STPCLK# timing follows Intel's own PIIX4 chipset throttle (32 µs shortest phase, 244 µs period) but has not been verified on a scope for every CPU family yet. The dashboard says so for each family.

## Quick Start: install the firmware

The easiest way is the web installer. Plug the ESP32‑C3 SuperMini into your computer and press "Install Firmware":

[![Install Firmware](https://img.shields.io/badge/Install-Firmware-orange?style=for-the-badge&logo=espressif)](https://bitsundbolts.github.io/hawk370-throttle/)
<br />*Use Google Chrome, Microsoft Edge, Opera or another Chromium browser (Firefox from version 151). Safari does not support Web Serial.*

The installer asks whether to **erase the device**:

| Choice | What happens | When |
|---|---|---|
| **Leave "Erase device" unticked** | Flash and **keep settings**: Wi‑Fi, CPU family, base clock and presets stay. The web pages are replaced. | Updating a HAWK 370 |
| **Tick "Erase device"** | Flash and **wipe all data**: the whole chip is erased first. | First install, or a board that ran other firmware |

After a fresh install, the board starts its own hotspot **`HAWK370-Setup`** (password `hawk370setup`). Connect to it and open `http://hawk370.local` (or `192.168.8.1`) to run the setup wizard. Choose whether to join your Wi‑Fi network or stay in standalone access‑point mode for bench use. Once it has joined your network, the dashboard is at `http://hawk370.local`.

The hotspot password is public on purpose. The hotspot is only for the local, one‑time setup (or for bench use without a router), and the HAWK 370 closes it once it has joined your network.

## Features

- **Two Wi‑Fi modes, one setup wizard.** Join your home/lab network, or run standalone as its own access point (`HAWK370-Setup`, password `hawk370setup`) with no router needed.
- **Live throttle control.** Drag the slider, use the 25 / 50 / 75 / 100 % buttons next to the MHz readout, or click the readout and type an exact value. The slider sends its value once it rests for a moment (250 ms) or when you let go, so the CPU is not re‑throttled on every step of a drag. Resolution is about 0.03 % from ~0.1 % to ~99.9 % of the base clock.
- **CPU family and base clock with APPLY.** Changing the family or base clock only changes the page. You can dial in the speed for the new CPU first, then press **APPLY** to send everything in one step, so a Mendocino never gets the 1200 MHz meant for a Tualatin.
- **Your own presets.** Save speeds like "386DX‑40 = 25 MHz" per CPU family (100 slots shared by all families) in a searchable A‑Z list. A preset stores the effective MHz, so one measured on a Tualatin 1400 gives the same speed on a Tualatin 1133. Rename, edit, delete, and export/import everything as one JSON file to share with others.
- **Pause at 0 MHz.** Holds STPCLK# asserted; the CPU resumes exactly where it stopped. Power‑on is always full speed, so the PC always POSTs.
- **Intel‑referenced, glitch‑free timing.** In the middle of the range the pattern uses the 440BX chipset's own 244 µs period with continuous duty; outside it the short phase stays at 32 µs and the period stretches. No STPCLK# phase is ever shorter than 32 µs, even while switching speed.
- **Live VCORE / VTT telemetry** over Server‑Sent Events with sparkline graphs. Several browsers stay in sync.
- **Web installer, OTA updates and file manager.** Install from the browser over USB, or update over Wi‑Fi by dropping files on the Files page.
- **Robust Wi‑Fi.** Joining your network never blocks boot. If it is not reachable, the `HAWK370-Setup` access point (password `hawk370setup`) comes up with the dashboard while the station keeps retrying.
- **Wi‑Fi power‑saving toggle.** Switch between low‑latency (`Max`) and power‑saving (`Eco`) modem modes on the fly.

## Using the dashboard

- **CPU family and base clock.** Pick the family from the dropdown and enter the CPU's full clock in MHz (▲/▼ or type it). The **APPLY** button lights up as soon as the page differs from what the HAWK 370 runs, and stays grey otherwise. Until you press APPLY (or Enter in the base clock field), the slider, % buttons and presets only move the target on screen. APPLY sends family, base clock and speed together; afterwards the slider works live again.
- **Speed.** Slider, the 25 / 50 / 75 / 100 % buttons beside the readout, or click the big MHz number and type a value (Enter or a click outside applies, Esc cancels). The line below shows the speed the CPU actually gets.
- **My presets.** Open the list, search, click a preset to apply it. "+ Save current" stores the current speed for the selected family; ✎ edits, renames or deletes. "Export all" / "Import…" move presets between devices.
- **Keys.** ← / → ±1 MHz, Shift ±10 MHz, 1–4 for the % buttons.
- **Power‑on** is always full speed with the stored family and base clock. The HAWK 370 never throttles the CPU while it boots.

## Updating: installer or Files page

| | Web installer (USB) | Files page (OTA over Wi‑Fi) |
|---|---|---|
| Firmware | ✔ | Drop `HAWK370_firmware.bin` |
| Web pages | ✔ | Drop `HAWK370_littlefs.bin` |
| Bootloader / partition table | ✔ | ✘ (never changed over OTA) |
| Wi‑Fi, CPU family, base clock, presets | Kept, unless "Erase device" is ticked | Always kept |
| Files you uploaded by hand | Replaced by the release's web pages | Kept with the firmware file; replaced by a `*littlefs*.bin` image |

How OTA works: a firmware file is written to the *other* app slot (the ESP32 has two, 1.25 MB each), checked, and only then booted. If the upload fails, the old firmware keeps running. A `*littlefs*.bin` replaces the whole web storage. Settings and presets live in NVS, the ESP32's separate settings partition, which neither kind of upload touches.

The Files page refuses the installer‑only files (`HAWK370_bootloader.bin`, `HAWK370_partitions.bin`, `boot_app0.bin`, merged images) and anything larger than its partition before uploading.

Presets survive every update. Only erasing the whole chip removes them (the installer's "Erase device", or *Erase All Flash Before Sketch Upload* in the Arduino IDE), so export them first.

## Hardware

Built for an **ESP32‑C3 SuperMini** on the HAWK 370 board.

| Signal | Pin | Notes |
|---|---|---|
| `STPCLK#` drive | GPIO 7 | Via onboard 2N7002, RMT TX output |
| VCORE sense | GPIO 0 (ADC1_CH0) | 10k/10k divider + 100nF |
| VTT sense | GPIO 1 (ADC1_CH1) | 10k/10k divider + 100nF |

The 2N7002 gate has a 10k pull‑down to VSS, so STPCLK# stays released while the ESP32 is in reset, flashing over USB, or not fitted. The STPCLK# waveform is looped entirely in RMT hardware, so Wi‑Fi activity can't introduce jitter into the timing.

On dual‑CPU boards only one HAWK 370 needs an ESP32: the 440BX chipset has a single STPCLK# output, so the boards very likely share one STPCLK# net between both slots (check continuity between the two slots' STPCLK# pins).

> ⚠️ **Buy a SuperMini with 4 MB flash.** The firmware, the second OTA slot and the web pages need the full 4 MB layout in `partitions.csv`. Check the laser marking on the chip: it should start with **`FH4`** (e.g. `FH4P4…`): **F** = flash inside the chip package, **H** = rated to 105 °C (avoid **N**, 85 °C), **4** = 4 MB flash.

## Build and flash it yourself

### 1. Arduino IDE setup

Open `ESP32_C3_SuperMini.ino` in the Arduino IDE 2.x with the ESP32 core 3.3.x and these settings:

- Board **ESP32C3 Dev Module**, *USB CDC On Boot: Enabled*
- Partition scheme: nothing to choose. The `partitions.csv` in the sketch folder is picked up automatically (same layout as the core's default 4 MB table).
- Libraries: `ESPAsyncWebServer` and `AsyncTCP` (ESP32Async), `ArduinoJson` 7. `ESPmDNS`, `DNSServer`, `LittleFS` and `Preferences` come with the core.

### 2. Build the release files

1. *Sketch → Export Compiled Binary*. This puts the compiled firmware into `build/esp32.esp32.esp32c3/` inside the sketch folder.
2. Double-click `Build_Release.bat` (Windows). It works from wherever the sketch folder is, finds `mklittlefs` from the ESP32 core by itself, packs the `data/` folder into a LittleFS image and collects everything in `release/`:

| File | Flash offset | Web installer | OTA (Files page) |
|---|---|---|---|
| `HAWK370_bootloader.bin` | `0x0` | ✔ | |
| `HAWK370_partitions.bin` | `0x8000` | ✔ | |
| `boot_app0.bin` | `0xE000` | ✔ | |
| `HAWK370_firmware.bin` | `0x10000` | ✔ | ✔ |
| `HAWK370_littlefs.bin` | `0x290000` | ✔ | ✔ |

If your Arduino data folder is not in the default place (`%LOCALAPPDATA%\Arduino15`), set the environment variable `MKLITTLEFS_EXE` to the full path of `mklittlefs.exe` before running the script.

### 3. Flash it

- **Web installer:** attach all five files to a GitHub Release (tag e.g. `v0.6`), see [`docs/worker/README.md`](docs/worker/README.md). The installer writes them one by one rather than as one merged image, which is what lets it keep the settings.
- **OTA over Wi‑Fi:** on the dashboard's Files page, drop `HAWK370_firmware.bin`, wait for the restart, then drop `HAWK370_littlefs.bin`. Each upload restarts the HAWK 370.
- **USB from the Arduino IDE:** *Upload* flashes the firmware. The web pages go separately, either with the [arduino-littlefs-upload](https://github.com/earlephilhower/arduino-littlefs-upload) plugin (Ctrl+Shift+P → *Upload LittleFS to Pico/ESP8266/ESP32*) or, once the firmware runs, by dropping `HAWK370_littlefs.bin` on the Files page.

**Why two files?** The ESP32 keeps the firmware and the web pages in separate areas, and each upload replaces one of them. The `ESP32_C3_SuperMini.ino.merged.bin` from *Export Compiled Binary* is not a shortcut: it has the firmware but no web pages, and it is too big for the Files page, which refuses it.

After flashing, continue with the Wi‑Fi setup described in the [Quick Start](#quick-start-install-the-firmware).

## API reference

| Endpoint | Method | Description |
|---|---|---|
| `/api/throttle` | GET | Family, base clock, requested %, delivered % and MHz, paused |
| `/api/throttle/config` | POST | Set CPU family + base clock, optionally the speed in the same step: `{"family":2,"baseMhz":1400,"speedPercent":25}` (without `speedPercent` the current % is kept) |
| `/api/throttle/speed` | POST | Set speed: `{"speedPercent":25}` (0 = Pause, 100 = full speed) |
| `/api/cpu-families` | GET | CPU families with their bench‑verified flag |
| `/api/presets?family=2` | GET | Presets of one CPU family, A‑Z |
| `/api/presets/save` | POST | Create or edit: `{"family":2,"name":"386DX-40","mhz":25,"refBaseMhz":1400,"originalName":"…"}` |
| `/api/presets/delete` | POST | `{"family":2,"name":"386DX-40"}` |
| `/api/presets/import` | POST | Merge `{"family":2,"presets":[…]}` (the dashboard splits export files by family) |
| `/api/telemetry` | GET | One‑shot voltage/temp/RSSI/memory snapshot |
| `/events` | SSE | `telemetry` every ~500 ms, `throttle` on every change, `presets` when presets change |
| `/api/system` | GET | Firmware version, IP, SSID, storage usage |
| `/api/ping` | GET | Liveness probe with boot id and setup‑mode flag (CORS open; used to find the device after a restart or Wi‑Fi reset) |
| `/api/system/wifi-ps` | POST | Toggle Wi‑Fi power saving |
| `/api/files/all` | GET | List files on LittleFS |
| `/api/files/rename` / `/api/files/delete` | POST | Manage stored files |
| `/ota/firmware` | POST | Flash firmware; with `?target=fs` a LittleFS image |
| `/ota/file` | POST | Upload a file to storage |
| `/api/restart` / `/api/factory-reset` | POST | Restart device / erase Wi‑Fi credentials |

## Firmware layout and tests

| File | Purpose |
|---|---|
| `ESP32_C3_SuperMini.ino` | `setup()` / `loop()` only |
| `hawk_config.h` | Pins, STPCLK# polarity, network identity, firmware version |
| `hawk_pattern.*` | STPCLK# timing maths: pure C++, tested on a PC |
| `hawk_throttle.*` | RMT output, glitch‑free switching, Pause, CPU families |
| `hawk_presets.*` | User presets per CPU family, one compact record in NVS |
| `hawk_rails.*` | VCORE / VTT monitoring |
| `hawk_net.*` | Wi‑Fi modes, setup wizard, background reconnect |
| `hawk_web.*` | REST API, SSE, OTA, file manager |
| `partitions.csv` | 4 MB flash layout: NVS, two OTA app slots, LittleFS, core dump |
| `Build_Release.bat` | Collects the release files (web installer + OTA) after *Export Compiled Binary* |
| `docs/` | Web installer page and its Cloudflare Worker (`docs/worker`) |

Web handlers only post requests; every pin, RMT, radio and NVS change happens in `loop()`.

Run the tests on a PC with `sh test/run_tests.sh` (needs g++ or clang++). The modulator test sweeps every speed and base clock and checks that no phase is shorter than the minimum and the delivered speed matches the request. The preset test (needs ArduinoJson, found automatically or via `ARDUINOJSON_SRC`) covers saving, renaming, merging imports, the 100‑slot limit and rolling back failed writes.
